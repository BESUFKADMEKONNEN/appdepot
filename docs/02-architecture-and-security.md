## 1. Filesystem Layout & Conventions

### 1.1 Default Install Root (`/opt/Application`)

In accordance with the Filesystem Hierarchy Standard (FHS), `/opt` is reserved for add-on software packages outside distribution control.

```
/opt/Application/
├── ide/                 # Antigravity, Android Studio, VS Code, JetBrains
├── sdk/                 # Flutter, Android SDK, OpenJDK, Rust toolchains
├── browsers/            # Linked: chrome -> /opt/google/chrome
├── databases/
│   ├── postgresql/      # Relocated database cluster (data directory)
│   └── mysql/           # Relocated database cluster
├── runtimes/            # Node, Deno, Bun (tarball installs)
├── network/             # NetBird, VPN utilities
├── office/              # Linked: onlyoffice -> /opt/onlyoffice
├── tools/               # Standalone binaries and utilities
└── .appdepot/           # AppDepot metadata root (hidden)
    ├── registry.db      # SQLite master registry & ledger
    ├── ledger/          # Backup transaction receipts
    ├── cache/           # Cached downloads and icons
    └── logs/            # Execution logs
```

### 1.2 Scopes: System vs. User

| Dimension | System Scope (Default) | User Scope (No-Sudo / Lab) |
|---|---|---|
| **Root Path** | `/opt/Application` | `~/Applications` |
| **Shortcuts** | `/usr/share/applications` | `~/.local/share/applications` |
| **Command Links** | `/usr/local/bin` | `~/.local/bin` |
| **Env Fragments** | `/etc/profile.d/appdepot.d/*.sh` | `~/.profile.d/appdepot.d/*.sh` |
| **Needs Privileges** | Yes (via `appdepot-helper`) | No (pure user space) |

### 1.3 Permissions Model & Setgid Bit

To allow unprivileged users in the developer group to manage software without typing `sudo` on every file write:

```bash
# Permissions hierarchy
/opt/Application             root:devtools   2775  (setgid, group-writable)
/opt/Application/<category>  root:devtools   2775
<app folder>                 <user>:devtools 2775
```

- **Setgid bit (`2775`):** Ensures that any new subdirectories and files automatically inherit the `devtools` group ownership.
- **Init step (`depot init`):** Creates group `devtools`, adds the current user, configures directory modes, and prompts the user that a session re-login is required to activate group membership.

### 1.4 Modular Environment Fragments

Rather than polluting `~/.bashrc` or `~/.zshrc` with brittle edits, AppDepot uses **one isolated fragment per application**:

```sh
# /etc/profile.d/appdepot.d/flutter.sh (Generated by AppDepot; do not edit)
export FLUTTER_HOME="/opt/Application/sdk/flutter"
export PATH="$FLUTTER_HOME/bin:$PATH"
```

A single system loader sources all fragments cleanly:

```sh
# /etc/profile.d/appdepot.sh
for f in /etc/profile.d/appdepot.d/*.sh; do [ -r "$f" ] && . "$f"; done
unset f
```
*Uninstalling an app removes its single fragment file, restoring environment hygiene immediately.*

## 2. Privilege and Security Model

### 2.1 Threat Model & Mitigations

| Threat Vector | Real-World Attack Scenario | AppDepot Mitigation |
|---|---|---|
| **Malicious Archive** | Zip-slip directory traversal (`../../etc/shadow`), decompression bomb | Path normalization check before extraction, quota limits on files and uncompressed bytes. |
| **Tampered Download** | Man-in-the-middle or poisoned mirror | Mandatory SHA-256 validation; GPG/minisign signature checks where available. |
| **Hostile Manifest** | Shared TOML script executing arbitrary commands | Post-install hooks are never run silently; require explicit user review & authorization. |
| **Privilege Escalation** | Compromised GUI sending arbitrary root commands | The helper accepts **only typed JSON requests**, never arbitrary shell commands. |
| **Shared Tree Tampering** | Local unprivileged user overwrites shared binary | Strict `2775` permissions, root-owned helper binary, polkit authorization. |
| **Over-Broad Removal** | Bug in uninstaller deleting `/opt` or user home | Ledger-based uninstaller removes strictly recorded artifact paths inside the install root. |

### 2.2 Privilege Separation Architecture

```
┌─────────────────────────────────┐
│     GUI / CLI (Unprivileged)    │
│    Runs as normal user session  │
└────────────────┬────────────────┘
                 │
                 │ Invokes via pkexec with Typed JSON request
                 ▼
┌─────────────────────────────────┐
│     Polkit Authorization        │
│   Action: org.appdepot.helper   │  <── Prompts for password if needed
└────────────────┬────────────────┘
                 │
                 │ Runs authorized privileged action
                 ▼
┌────────────────────────────────────────────────────────┐
│        appdepot-helper (Root binary in /usr/libexec)   │
├────────────────────────────────────────────────────────┤
│  • install_tree (creates category dirs with 2775)      │
│  • set_sandbox (chown root:root & chmod 4755)          │
│  • write_system_shortcut (/usr/share/applications)     │
│  • write_env_fragment (/etc/profile.d/appdepot.d)      │
│  • manage_service (starts/stops systemd unit)          │
│  • write_audit_log (/var/log/appdepot/audit.log)       │
└────────────────────────────────────────────────────────┘
```

### 2.3 Helper Design Invariants

1. **Typed Operations Only:** Helper reads strict JSON on `stdin` (e.g. `{"op": "set_sandbox", "path": "/opt/Application/ide/antigravity/chrome-sandbox"}`). It **never** receives shell command strings.
2. **Path Canonicalization:** Helper resolves symlinks and rejects any path outside `/opt/Application`, `/usr/share/applications`, or `/etc/profile.d/appdepot.d/`.
3. **No Network Access:** Helper does not touch the network. All downloads and checksum verifications happen in the unprivileged user process.
4. **Audit Logging:** Every invocation is appended to `/var/log/appdepot/audit.log` with timestamp, UID, operation, and outcome.

## 3. System Architecture

### 3.1 Layered Architecture Overview

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ PRESENTATION LAYER                                                           │
│  ┌───────────────────────────┐        ┌──────────────────────────────┐       │
│  │ GUI (Tauri v2 + Webview)  │        │ CLI (`depot`) Binary         │       │

│  └──────────────┬────────────┘        └──────────────┬───────────────┘       │
├─────────────────┼────────────────────────────────────┼───────────────────────┤
│ APPLICATION LAYER (appdepot-core Rust Library)                               │
│  ┌──────────────▼────────────────────────────────────▼───────────────────┐   │
│  │ Job Queue · Event Bus · Transaction Manager · Policy Engine           │   │
│  ├───────────────────────────────────────────────────────────────────────┤   │
│  │ Pipeline Engine │ Analyzer & Heuristics │ Shortcut Generator │ Doctor │   │
│  ├───────────────────────────────────────────────────────────────────────┤   │
│  │ Source Adapters: tarball · zip · deb · appimage · git · apt · flatpak │   │

```

### 3.2 The "Plan, Then Apply" Pattern

Every mutating operation (install, update, repair, remove) first produces a declarative `Plan` containing typed actions. This guarantees:
- **Dry runs are identical to real executions** (`depot install ... --dry-run`).
- **The GUI can display an exact preview** before any file is touched.
- **Failures trigger transactional rollbacks** using the plan's receipts.

```rust
pub enum Action {
    CreateDir   { path: PathBuf, owner: Owner, mode: u32 },
    ExtractTo   { archive: PathBuf, dest: PathBuf, strip: StripMode },
    Symlink     { target: PathBuf, link: PathBuf },
    WriteFile   { path: PathBuf, contents: Vec<u8>, mode: u32 },
    SetSandbox  { path: PathBuf },
    EnvFragment { app_id: String, shell: Shell, body: String },
    Service     { unit: String, op: ServiceOp },
    Register    { entry: Entry },
}

pub struct Plan {
    pub actions: Vec<Action>,
    pub needs_privilege: bool,
}

pub trait Executor {
    fn apply(&self, plan: &Plan, ctx: &mut JobCtx) -> Result<Receipt>;
    fn rollback(&self, receipt: &Receipt) -> Result<()>;
}
```

/// Pluggable source handler (tarball, zip, deb, appimage, git)
pub trait SourceAdapter: Send + Sync {

## 4. Data Model (SQLite Registry)

Located at `/opt/Application/.appdepot/registry.db` (System) or `~/.local/share/appdepot/registry.db` (User).

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE category (
  id         TEXT PRIMARY KEY,
  label      TEXT NOT NULL,
  icon       TEXT,
  sort_order INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE app (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  category_id  TEXT REFERENCES category(id) ON DELETE SET NULL,
  mode         TEXT NOT NULL CHECK (mode IN ('managed','linked','adopted')),
  version      TEXT,
  install_path TEXT,
  exec_path    TEXT,
  icon_path    TEXT,
  source_type  TEXT NOT NULL,
  source_ref   TEXT,
  checksum     TEXT,
  trust_level  TEXT NOT NULL DEFAULT 'unverified',
  pinned       INTEGER NOT NULL DEFAULT 0,
  installed_at TEXT NOT NULL,
  updated_at   TEXT
);

CREATE TABLE artifact (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  app_id       TEXT NOT NULL REFERENCES app(id) ON DELETE CASCADE,
  kind         TEXT NOT NULL CHECK (kind IN
                 ('dir','symlink','desktop_entry','env_fragment',
                  'wrapper','service_override','mime','sandbox_fix')),
  path         TEXT NOT NULL,
  content_hash TEXT,
  created_at   TEXT NOT NULL
);

CREATE TABLE tag (
  app_id TEXT NOT NULL REFERENCES app(id) ON DELETE CASCADE,
  tag    TEXT NOT NULL,
  PRIMARY KEY (app_id, tag)
);

CREATE TABLE stack (
  id    TEXT PRIMARY KEY,
  label TEXT NOT NULL,
  notes TEXT
);

CREATE TABLE stack_member (
  stack_id TEXT NOT NULL REFERENCES stack(id) ON DELETE CASCADE,
  app_id   TEXT NOT NULL REFERENCES app(id)   ON DELETE CASCADE,
  position INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (stack_id, app_id)
);

CREATE TABLE service (
  id        TEXT PRIMARY KEY,
  app_id    TEXT REFERENCES app(id) ON DELETE SET NULL,
  unit      TEXT NOT NULL,
  autostart INTEGER NOT NULL DEFAULT 0,
  data_dir  TEXT
);

CREATE TABLE job (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  kind        TEXT NOT NULL,
  target      TEXT,
  state       TEXT NOT NULL CHECK (state IN
                ('queued','running','succeeded','failed','cancelled')),
  started_at  TEXT,
  finished_at TEXT,
  error_code  TEXT
);

CREATE TABLE job_log (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  job_id  INTEGER NOT NULL REFERENCES job(id) ON DELETE CASCADE,
  ts      TEXT NOT NULL,
  level   TEXT NOT NULL,
  message TEXT NOT NULL
);

CREATE TABLE schema_version (version INTEGER NOT NULL);
```

### 4.1 Invariants
1. **Ledger as the Single Source of Truth:** `artifact` records are the only paths consulted during uninstallation.
2. **Transaction atomicity:** Registry records are written inside an SQLite transaction only *after* filesystem actions succeed.
3. **Disaster Recovery:** A built-in command (`depot doctor --rebuild-registry`) can reconstruct the database by scanning `X-AppDepot-Id` metadata from existing `.desktop` shortcuts.

## 5. Technology Stack Decisions

| Subsystem | Selection | Justification |
|---|---|---|
| **Core Language** | **Rust** | Memory safety, native systems bindings (ELF, D-Bus, PTY), single-binary CLI, high portfolio value. |
| **Desktop Shell** | **Tauri v2** | Lightweight native webview wrapper, minimal memory footprint (<150 MB idle vs 400+ MB Electron). |
| **Frontend** | **React + TypeScript + Vite** | Fast feedback loop, rich developer tooling, shared typed interfaces with Rust backend. |
| **UI Components** | **Radix UI + Vanilla CSS / Tailwind** | Accessible primitives, customizable design tokens, native look and feel. |
| **Embedded Terminal** | **`xterm.js` + `portable-pty`** | Battle-tested terminal engine (used by VS Code), real PTY streaming over Tauri channels. |
| **CLI Framework** | **`clap` v4 (derive)** | Type-safe argument parsing, automated `--help` and shell completion generation. |
| **Database** | **`rusqlite` (bundled SQLite)** | Transactional, zero external daemon, inspectable via standard sqlite3 CLI. |

### 5.1 Fallback Tripwires (Plans B & C)
- **Plan B (Flutter Desktop):** If the Rust core encounters blockers after Phase 3, the frontend can be ported to Flutter Linux desktop while retaining the underlying concepts.
- **Plan C (Qt / Kirigami):** If WebKitGTK exhibits display bugs across niche Wayland environments, GTK4 or Qt can wrap `appdepot-core`.
